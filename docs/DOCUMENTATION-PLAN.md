## 1. README.md
**Contents**: project presentation — what it does, how to start it (`docker-compose up`), architecture diagram/screenshot, tech stack.
**Why**: it's the first file a recruiter or tech lead reads.

## 2. ARCHITECTURE.md
**Contents**: technical deep dive — sequence diagrams for the Saga flow, overall architectural decisions and why (e.g. "why Kafka instead of RabbitMQ" — here: why RabbitMQ was chosen instead of Kafka, "why orchestrated Saga instead of choreographed").
**Why**: shows deep understanding of the design, not just that "it works".

## 3. API.md
**Contents**: REST endpoints for each service, example request/response, error codes. (Alternative: OpenAPI/Swagger auto-generated by Spring Boot.)
**Why**: standard technical documentation, also useful for testing with Postman.

## 4. DECISIONS.md (Architecture Decision Records)
**Contents**: log of choices made during development, with rationale and discarded alternatives (e.g. "chose PostgreSQL per service instead of a shared DB because...").
**Why**: a ready answer for "why did you choose X instead of Y" in interviews, without having to remember from scratch.

## 5. LEARNINGS.md
**Contents**: problems encountered during development and how they were solved (e.g. "an event wasn't propagating because...").
**Why**: prepares for questions like "tell me about a difficulty you faced".

## 6. DEPLOYMENT.md
**Contents**: instructions for local startup with Docker Compose, required environment variables, common troubleshooting (e.g. DB healthchecks not ready).
**Why**: makes the project reproducible by anyone in a few minutes.

---

## How to use them with the AI

As development starts, keep these files updated as you go and provide them to the AI as context when asking for help — in particular:
- **ARCHITECTURE.md** and **DECISIONS.md** when asking for help with new features, so the AI respects choices already made instead of re-proposing alternatives
- **LEARNINGS.md** when you have a problem similar to one already solved
- **API.md** when working on integration between services
